# NEPAM · исходный код лендинга

## Публикация на GitHub Pages

Страница собирается и публикуется автоматически при каждом изменении ветки `main`. Устанавливать на компьютер ничего не нужно.

1. На github.com создайте репозиторий, например `nepam-landing`. На бесплатном тарифе Pages работает только с публичными репозиториями, поэтому исходники будут видны всем. Ветка по умолчанию должна называться `main`.
2. На странице репозитория нажмите **uploading an existing file** и перетащите всё содержимое этой папки, включая папку `.github`. Нажмите **Commit changes**.
3. Проверьте, что в репозитории есть файл `.github/workflows/pages.yml`. Если его нет, нажмите **Add file → Create new file**, введите этот путь в имени файла и вставьте содержимое из архива.
4. Откройте **Settings → Pages** и в поле **Source** выберите **GitHub Actions**.
5. Откройте вкладку **Actions**, выберите **Deploy to GitHub Pages** и нажмите **Run workflow**.
6. Когда запуск завершится, сайт откроется по адресу `https://ИМЯ-АККАУНТА.github.io/nepam-landing/`.

### Заявки на GitHub Pages

GitHub Pages отдаёт только статические файлы, поэтому `server.mjs` и база заявок там не работают. Вместо формы показывается кнопка, которая открывает рабочую форму и передаёт выбранный сценарий. По умолчанию это форма NEPAM в Sites.

Чтобы вести на другую форму, откройте **Settings → Secrets and variables → Actions → Variables** и создайте переменную `PILOT_FORM_URL` с адресом формы, начинающимся с `https://`. Затем снова запустите **Deploy to GitHub Pages**.

Собрать страницу для Pages локально можно командой `node site/build-pages.mjs` из папки с этим README. Результат появится в `dist/index.html`.

## Запуск в VS Code

1. Распакуйте архив и откройте папку `site` в VS Code.
2. Установите Node.js 24 или новее (https://nodejs.org). В терминале этой папки выполните `node server.mjs`.
3. Откройте http://127.0.0.1:8080. Демо и форма работают локально. Для остановки нажмите Ctrl+C.

Сервер автоматически собирает страницу при запуске. После изменений перезапустите его.

| Файл | Что редактировать |
| --- | --- |
| `index.template.html` | текст и разметка |
| `style.css` | стили и анимации |
| `client.js` | демо, сценарии, форма |
| `core.svg` | иллюстрация шлюза |
| `index.html` | не редактировать, это собранная страница. При открытии с диска форма требует запущенный сервер |

Прямая ссылка на демо по времени — `/#demo-time`. Предвыбор сценария — `/?scenario=Администрирование`.

### Настройка демо

Значения окна допуска заданы константами `OPEN` и `CLOSE` в `client.js`, в минутах от начала суток. Варианты выбора лежат в `labs.time.options` и `labs.api.options`. Подпись результата для времени считается из выбранного значения, поэтому новый вариант не требует отдельного текста. Отметки на шкале заданы в `style.css`: 37,5% соответствует 09:00, 75% соответствует 18:00.

### Заявки и самостоятельное размещение

Заявки локальной копии сохраняются в `site/data/pilots.sqlite`. В терминале папки site выполните `node server.mjs --leads` для просмотра. Пример выгрузки JSON в файл — `node server.mjs --leads > leads.json`. Доступ к списку имеет оператор сервера через терминал.

Для размещения на своём сервере перенесите папку site, запустите её Node-процесс и направьте HTTPS-прокси домена на его порт. Задайте `PUBLIC_ORIGIN` равным публичному адресу с протоколом, например `https://nepam.example.org`. Для прослушивания адреса контейнера задайте `HOST=0.0.0.0`. Порт задаётся переменной `PORT`. Путь к постоянной базе задаётся через `NEPAM_DB`. Прокси должен передавать запросы процессу, а каталог с базой должен находиться вне публично раздаваемых файлов. Локальная копия создаёт собственную базу. Исторические заявки опубликованной версии в архив не включены.

## Публикация на Tilda

1. На пустой странице добавьте блок **T123 «HTML-код»** из категории «Другое».
2. Откройте `tilda/T123.html` в текстовом редакторе, скопируйте всё содержимое в блок и опубликуйте страницу. Код не выполняется в редакторе Tilda, проверяйте опубликованную страницу в современном браузере. Справка Tilda — https://help-ru.tilda.cc/html
3. По умолчанию кнопка заявки ведёт на действующую форму NEPAM в Sites и передаёт выбранный сценарий. Сами демо, графика и стили встроены в T123.
4. Прямая ссылка `#demo-time` и параметр `?scenario=` работают и на странице Tilda: код читает адрес страницы, на которую вставлен.

### Подключение штатной формы Tilda

1. Добавьте под T123 блок формы. Настройте поля имени, компании, почты и согласия, подключите нужный приёмщик данных.
2. Для передачи сценария добавьте текстовое или скрытое поле с именем переменной `scenario`.
3. Узнайте ID блока формы: `#rec` и число из настроек блока.
4. В начале кода T123 укажите его в `NATIVE_FORM`, например `const NATIVE_FORM = '#rec123456789';`. Либо соберите код сразу с ID, как показано ниже.
5. Опубликуйте страницу и отправьте тестовую заявку. Если ID пуст или блок не найден, кнопка открывает форму Sites.

### Как обновить код T123 после правок

Из папки с этим README выполните `node tilda/build-t123.mjs`, либо `node tilda/build-t123.mjs #rec123456789`, чтобы подставить ID формы. Скрипт заново собирает страницу и генерирует компактный `tilda/T123.html`. Вставьте обновлённый код и опубликуйте страницу.
